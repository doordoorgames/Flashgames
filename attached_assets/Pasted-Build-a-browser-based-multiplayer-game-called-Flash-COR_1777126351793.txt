Build a browser-based multiplayer game called “Flash / لمحة”.

CORE GAME:
- Players join using a 5-digit room code.
- One player is admin.
- Admin starts the game from the lobby.
- Game runs for 9 rounds total.

ROUND STRUCTURE:
- Rounds 1–3 (Easy): flashDuration = 600ms
- Rounds 4–6 (Medium): flashDuration = 300ms
- Rounds 7–9 (Hard): flashDuration = 150ms

Each round flow:
1. Show round number + difficulty label (Easy / Medium / Hard).
2. Show a 3-second countdown (large centered).
3. Flash the content (image / logo / number / symbol) for the correct duration.
4. Immediately hide it.
5. Players type their answers into an input box.
6. Show live submitted answers ONLY to admin.
7. After time ends (10 seconds), lock answers.
8. Reveal correct answer + highlight winners.
9. Award points based on speed:
   - First correct: 5 points
   - Second: 3 points
   - Others correct: 1 point
10. Admin clicks “Next Round”.
11. After round 9 → show final leaderboard.

ANSWER VALIDATION (IMPORTANT):
- Normalize all answers:
  - lowercase
  - trim spaces
  - remove punctuation
- Each item has:
  correctAnswer: string
  acceptedAnswers: array

- Accept answer if:
  1. Exact match with correctAnswer
  2. Match any acceptedAnswers
  3. Fuzzy match using Levenshtein distance:
     - 3–5 letter words → allow 1 typo
     - 6+ letters → allow 2 typos
     - Numbers must match exactly unless explicitly listed in acceptedAnswers

UI / DESIGN (VERY IMPORTANT — DO NOT BREAK THESE RULES):

SCREEN:
- Must work in full screen on all devices.
- No white edges EVER.
- Background must always fill entire screen with dark grey/black tones.

TOP AREA:
- Top 20% of screen = solid dark grey (#1a1a1a)
- This area must stay clean and empty to blend with mobile browser URL bar.
- No important UI elements here.

BACKGROUND:
- Bottom 80% = stylized night cityscape.
- Buildings:
  - Random heights (7, 9, 14 floors)
  - Windows glow in neon colors (blue, pink, yellow)
  - Subtle animation: windows flicker randomly

SKY EFFECT:
- Above buildings (still under top grey zone):
  - Small subtle stars (slow twinkle animation)
  - Shooting star appears randomly every ~10 seconds (fast diagonal streak)

FLASH AREA:
- Center of the screen (upper-middle, NOT too low due to TikTok comments)
- Display content on a billboard-style panel:
  - Rectangular
  - Slight neon outline (yellow or pink)
  - Clean, NOT rounded bubble style

FLASH LOGIC:
- Content fades in instantly → stays visible for flashDuration → disappears instantly
- No slow fade-out (must feel sharp and fast)

INPUT UI:
- Player input box should appear right after flash disappears
- Large, centered, easy to type
- “Submit” button or auto-submit on enter

ADMIN VIEW:
- Admin sees:
  - list of player answers in real-time
  - correct answers highlighted after reveal
  - “Next Round” button
  - “End Game” button

PLAYER VIEW:
- Players only see:
  - countdown
  - flash
  - input field
  - result after reveal

DATA STRUCTURE:
Use JSON or CSV like:

type, prompt, mediaUrl, correctAnswer, acceptedAnswers, flashDurationMs, timeLimitSeconds

Example:
image, Lion, /uploads/lion.png, lion, ["lion","lions","أسد","الأسد","asad"], 600, 10

PERFORMANCE:
- Flash timing must be precise (use setTimeout or requestAnimationFrame)
- No lag between flash and hide
- Optimize for mobile browsers

AUDIO (OPTIONAL BUT PREPARED):
- Tick sound during countdown
- Quick “flash” sound
- Success sound on correct answers

FINAL RULE:
Do NOT change layout proportions, background logic, or top grey area behavior when adding new features later.
Everything must stay visually consistent.
